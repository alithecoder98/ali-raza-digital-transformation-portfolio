How I think about AI solutions

  • LLM or not? If a rule, a query or a script does the job reliably, I use that. LLMs go where the input is messy or language-heavy.
  • Model choice follows the task, cost and data constraints. I compare GPT, Claude, Gemini and open models rather than defaulting to one.
  • Structured outputs and prompts make AI steps testable and keep them from improvising.
  • RAG when answers must come from the business's own documents.
  • Agents only where multi-step decisions really help, with clear limits on what they can do.
  • Evaluation first. I define what "good" looks like, test against it, and watch for hallucinations.
  • A person in the loop wherever a wrong answer is expensive.

Enterprise start-of-shift reporting automation

Each shift used to start with someone collecting health metrics from several systems by hand. I automated the whole cycle, from data collection to a consolidated report emailed to the team, and it now runs on a schedule every eight hours.

~45 minsaved per reporting cycle, three cycles a day

How it works

1. Data sources
  • Server health & utilization
  • Hadoop cluster health
  • SQL Server & CDC latency
  • Storage & directory sizes

2. Scheduled collectionPowerShell and shell scripts, run every 8 hours
→
3. ConsolidateAll metrics combined into one standard report format
→
4. DeliverThe consolidated report is emailed to the shift team

Simplified and anonymized. No hostnames or client details.

Read the full case study

Business context

A managed-services team supporting banking environments had to confirm platform health at the start of every shift before any other work could begin.

Problem

The report was compiled manually from server, Hadoop, database, CDC and storage sources. It was slow, repetitive, and easy to get wrong on a busy shift.

My role

Mapped the manual process, defined which metrics the report needed, built the scripts and scheduling, and rolled it out to the operations team.

Tools & techniques

PowerShellShell scriptingSQL ServerHadoopCDC monitoringTask schedulingEmail automation

Results

  • About 45 minutes of manual effort removed from each cycle
  • A consistent report format, improving operational visibility and record-keeping
  • Platform status visible at the start of every shift

Lessons learned

Agreeing on what the report had to contain took longer than writing the scripts, and it mattered more. Not every automation needs AI. Here, scheduled scripts were the reliable choice.

AI-powered quality assurance & LLM process design

I designed and documented structured SOP validation criteria and an evaluation workflow to support consistent, AI-assisted call-center quality assessment. I also evaluate the outputs of our LLM pipelines and agents.

StructuredQA criteria, ready for AI-assisted evaluation
Read the full case study

Business context

Call-center quality reviews check agents against SOPs. This is a natural fit for AI assistance, but only if the criteria are precise.

Problem

The review criteria lived in reviewers' heads and loose documents, so results were inconsistent and could not be automated.

My role

Designed and documented the SOP validation and evaluation workflow, and reviewed LLM and agent output to find quality gaps and workflow issues.

Solution approach

Broke each SOP into explicit, checkable criteria with clear pass/fail logic, documented so they can be applied consistently in AI-assisted evaluation and verified by a reviewer.

Tools & techniques

LLM evaluationPrompt & output structureProcess designJiraAgile

Results

  • A documented, repeatable QA process instead of ad-hoc judgment
  • Quality gaps in pipeline output turned into actionable engineering feedback

Lessons learned

Most of the work in AI evaluation happens before the model: once the criteria are unambiguous, a person and an LLM can apply them the same way.

Prototype

RAG knowledge assistant

Answers questions over PDFs and web pages for different domains, with LangGraph orchestrating the agent steps.

PythonLangGraphChromaDBGeminiStreamlit
How it works

Problem

Finding answers in long documents is slow, and plain chatbots make up answers that aren't in the source.

Architecture

Documents are chunked and embedded into ChromaDB. A LangGraph flow retrieves relevant passages and has Gemini answer only from them. Streamlit provides the interface.

What I learned

Retrieval quality, meaning chunking and search, matters more to the answer than the choice of model.

Prototype

AI résumé screening application

Reads a batch of résumé PDFs, extracts skills and experience with Gemini, and ranks candidates against a job description.

FlaskGeminiFAISSPyMuPDF
How it works

Problem

Screening a large pile of CVs by hand is slow and inconsistent.

Architecture

PyMuPDF extracts the text and Gemini structures the skills and experience. FAISS similarity scores each candidate against the job description, and the results export to CSV.

Responsible use

Built as a decision-support prototype, not an automated hiring system. Rankings need human review and should be evaluated for bias and fairness before any real use.

Multi-model LLM chat application

One conversation layer over OpenAI, Claude and Gemini through OpenRouter, keeping context consistent across turns.

PythonOpenRouterOpenAIClaudeGemini
How it works

Problem

Comparing models side by side is awkward when each one has its own API.

Architecture

A small abstraction routes requests through OpenRouter and keeps one shared conversation history, so you can switch models without losing context.

What I learned

Models differ a lot in tone, cost and reliability on the same task. That is why I compare them before choosing one.
